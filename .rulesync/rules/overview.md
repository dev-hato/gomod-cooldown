# Guide for working in this repository

This file provides guidance to AI agents when working with code in this repository.

`CLAUDE.md`, `AGENTS.md`, and `.github/copilot-instructions.md` are generated by rulesync.
Do not edit them directly; edit `.rulesync/rules/` and then run `npx --no-install rulesync generate`.

## Commands

Run the core checks listed in `CONTRIBUTING.md` (`.github/workflows` is authoritative). `golangci-lint` is pinned in `.tool-versions`; `govulncheck` is a `go.mod` tool dependency: `go tool golang.org/x/vuln/cmd/govulncheck ./...`.

Tests must be deterministic and never touch the network: use `httptest.Server`, injected `http.Client`/clocks, and local fake GOPROXY data. End-to-end tests in `internal/cli` build the CLI and run the real `go` command against a fake proxy, including fixed `go.mod` snapshots under `internal/cli/testdata/large-modules` (provenance recorded there and in `THIRD_PARTY_NOTICES.md` — update it when copying upstream files). Process-group/PTY tests are `darwin || linux` only and skip without the `script` utility.

## Generated docs

`README.md`, `README.ja.md`, and `CONTRIBUTING.md` are generated from `*.template.md` via `envsubst '$GO_VERSION'` in `.github/workflows/format.yml`. Edit the templates (and keep the English and Japanese READMEs in sync); edit the generated files only to match. The format workflow also runs `go fix`, `golangci-lint fmt`, `rulesync generate`, and `npx prettier --write .` and opens a follow-up PR with the diff.

## Architecture

`gomod-cooldown [flags] -- command [args...]` starts a loopback-only GOPROXY, runs the child with `GOPROXY` set to only that local URL (no `,direct` fallback, by design: a discovery 404 must not bypass the cooldown), then shuts the proxy down. Filtering behavior is specified in the README's "What is filtered" and "Availability time" sections.

## Compatibility constraints

v1 commits to flag names/meanings, defaults, stdout vs. stderr usage, documented exit codes (0, 1, 2, 126, 127, child status, 128+signal), the platform signal behavior, and the module path. Treat changes to any of these as breaking; record behavior corrections in `CHANGELOG.md`.
